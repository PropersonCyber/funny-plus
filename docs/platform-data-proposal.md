# Funny+ 平台数据与判断方案（讨论稿）

状态：产品方案草稿；不代表已实现。与 `ai-native-mvp.md` 配合使用，实施前需补齐待决规则和验收数据。

## 目标与边界

Funny+ 自主维护旅行内容、判断规则与反馈记录，解释某个选择为什么适合当前用户；外部地图、路线和公开事实仍可作为有来源的输入。首期服务北京样板区域的提前规划与现场推荐。

已确认方向：以北京为首期试点；主要事实以官方来源和平台核验为依据，用户数据作为参考帖或反馈，辅助用户判断与平台复核；不以早期样本不足的数据构造平台评分或热度。平台自有是对内容、规则和维护过程的掌握，不表示外部事实或第三方权益归平台所有。

## 数据分类

| 类型 | 例子 | 产生方式 | 使用边界 |
| --- | --- | --- | --- |
| 地点事实 | 坐标、入口、营业、票价 | 官方及第三方来源、人工核验、用户补充 | 每条事实记录来源、采集和核验时间、适用条件、有效期及状态；未知不当作免费或全天开放 |
| 平台内容 | 玩法、建议停留、机位、避坑 | 编辑整理，引用可靠来源或明确标注实地记录 | 区分编辑建议、用户经历和已核验事实；记录作者、依据、复核与版本 |
| 用户记录 | 确认到访、文字、照片、反馈 | 用户主动产生 | 默认私人；公开分享与参与平台汇总分别征得相应授权，不将计划推断为到访 |
| 平台判断 | 可行性、适合度、推荐理由 | 事实、确定性规则与本次旅行上下文 | 保留输入、规则版本、未知项和计算结果；不冒充事实或官方意见 |

一个地点的坐标、营业时间和票价可能来自不同来源并分别过期。目标口径按字段或独立事实追溯，不因坐标可信而将票价标为可信；现有行级 `trust` 到目标口径的迁移方案待设计。

## 数据生产与维护

1. 采集候选，去重并记录来源、获取时间和授权范围；未经核实的信息进入待核验状态。
2. 编辑核对内容与适用条件，保留证据；审核后发布。现场经历必须区分亲历与转述。
3. 到达有效期、来源变化或收到冲突反馈时，进入待复核；高风险且过期的时刻或价格不得作为硬约束，具体期限按字段另定。
4. 用户提交作为经验参考或复核线索，不自动等同或覆盖官方事实。记录处理结果、理由和版本；重大冲突在复核前如实提示。参考帖的发布、审核及隐私规则另行确定，不将私人记录自动公开。
5. 修订可回溯，错误可撤回；展示、AI 工具与行程引擎读取一致的事实与状态。

现有实现对反馈降级使用最少 3 票及 60% 负面比例；这是现有代码行为，不是已确认的长期产品规则。用户补录现已改为仅保存待复核，不再按账号投票自动写入地点或线路。可在 `server/` 执行 `npm run review:submissions` 只读查看待核验队列；审核决定、证据留存与发布入口尚待实现。

## 推荐与计算口径

先判断可行，再在可行候选中排序；系统应返回可解释的依据，缺数据时说明而非补造。

- 可行性：营业与日期、去程、游玩、转场、回程、必要缓冲，以及用户明确的时间、体力和固定安排。硬约束已知不满足时不可标为可行；未知时标明待确认。
- 个性化排序：以已确认的同行人、偏好、距离、步行强度与预算为输入；排序权重及缺失值策略通过样板场景验证后决定。临时状态不自动写成长期偏好。
- 时间：分列去程、等待、停留、转场、返回和缓冲；分别标注路线服务、平台核验或估算。硬性返回约束包含返回约定终点的时间；终点未知时询问或明确未覆盖。
- 费用：分列门票、交通、餐饮与其他项目，明确全团、人均、人数与分车假设；展示已知费用合计及未计入的未知项目，零元只表示已确认免费。
- 解释示例：候选 A 步行约 15 分钟、建议停留约 1 小时、可用时间 3 小时；门票待核实。每个数字须对应其事实或计算依据。

权重、步行阈值、缓冲时间、数据有效期、样本门槛均未定；不可将示例数值当生产规则。

## 样板与验收

首期试点城市为北京。选择其中一个区域作为首批样板，维护覆盖吃、玩、拍及地点相关避坑的小批数据，核实来源、位置与可用性。具体样板区域、数据量、核验责任人和周期待确定。

1. 带老人、剩余四小时的用户能看到候选可行性、推荐依据与未知项。
2. 改为硬性返回时间后，计算包含返回终点；不可行方案被说明而不标为可行。
3. 未核实价格不显示免费、不混入已知费用合计；过期信息不冒充当前已核验。
4. 用户反馈与事实冲突时可追溯并进入复核；私人记录未授权不进入公开内容或平台汇总。
5. 推荐、行程与对话对同一事实使用一致的数据和可信状态；可追溯结果所用数据与规则版本。
6. 两条 MVP 北京验收旅程在真实数据与真实模型下跑通，记录失败、耗时及人工维护成本。

## 暂不纳入与待决事项

首期暂不做平台综合评分、热度榜、自动由模型生成未经核验的事实，也不将匿名设备标识视为独立真实用户。地图与路线等外部能力仍可使用，须核对实际授权和使用条件。

待决：样板区域及最小内容集；事实分级、过期和冲突处理规则；编辑及复核责任；推荐与体力权重；用户授权与撤回方式；是否以及何时让反馈参与公开汇总。这些决策完成后再拆实施方案和排期。
